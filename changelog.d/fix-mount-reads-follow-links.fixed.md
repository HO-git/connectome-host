- The web UI's `/files/<mount>/<path>` route, the instructions module and the activity module's origin hint read workspace files through agent-framework's `readFileFromDisk`. It refuses a file that is itself a link unless its mount follows links, and reads a file only if its canonical path lies inside the mount, which it checks after opening the file. Before, the route and the origin hint resolved the path by its text and read it with Node's file calls, which follow any link: a link inside a mount let the files route serve a file from outside the mount to whoever could open it, and let the activity module read the first 2 KiB of such a file for a routing hint. The instructions module checked containment itself, by realpath, before it opened the file. The files route now answers 403 for a path no mount holds or one leading out of it, a file that is itself a link, or one whose canonical path lies outside the mount, 503 for a mount the read can't resolve after finding the file, and 404 for anything else the read can't give, such as a mount whose directory has gone, or a file that changed while it was read, which before was served as it was read. An answer for a read that was refused gives the read's reason as its body. The activity module skips such a file, and the instructions module injects nothing for it.
